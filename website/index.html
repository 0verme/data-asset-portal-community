02 / 问资产

问资产，
不是问数。

DAP 不直接回答数字。它用可追溯的方式找出对的资产：哪张表、哪个字段、口径写在哪、数据从哪来。再通过 API 把检索和可信数据能力，交给问数等上层应用使用。

  • 只展示真实执行步骤：检索词、检索轮次、命中资产、证据来源。
  • 不展示模型内部推理。
  • AI 问答默认关闭，是可选能力。

03 / 资产就绪度

用着用着，
就把资产补全了。

每个模块里有多少资产说得清楚、口径有出处，用一个百分比提示。它只是提示，用最小的代价让人知道哪里还缺。

各模块就绪度

示意数据
  • 表资产82%

    计入：有负责人和表说明

  • 字段含义64%

    计入：已填写中文含义

  • 指标口径71%

    计入：有口径文本和出数表

  • 码值90%

    计入：有码值说明

  • 报表与 API55%

    计入：已关联到具体资产 待补

  • 血缘快照38%

    计入：已导入快照的表占比 待补

百分比 = 满足条件的资产数 ÷ 该模块资产总数；低于 60% 标「待补」。以上百分比与阈值均为示意数据 [口径待确认]。

04 / 边界

它明确
不做什么

不

DAP 只做数仓资产目录这一件事，并且尽量让它能在内网的一台机器上跑起来。下面四件事，它不做，也不打算做。

不做 01

数据采集与调度

不负责真实数据采集、任务编排或文件推送执行。由外部系统整理好元数据后，通过 Metadata Contract 导入。

不做 02

扫描与解析

不主动发现数据：不扫描数据库，不解析 SQL。

不做 03

血缘计算

只浏览已导入的血缘快照，不做自动解析。

不做 04

质量与治理工作流

不提供数据质量检测、Profiling 和治理审批流程。资产就绪度只是提示，不带审批、工单或流转。

如果你需要这些能力，OpenMetadata 或 DataHub 可能更合适。这是定位差异，不是能力高低。
